BUILD NOTES / 01

BEHIND THE
BUILD.

A closer look at how PauzeWeather is put together — from live forecast data to a short AI weather briefing.

PROJECT / PAUZEWEATHER

An Android weather client built with Kotlin and Jetpack Compose.

01 / DATA LAYERWEATHERAPI

From location to forecast.

PauzeWeather sends a location query to WeatherAPI's forecast endpoint. The repository parses the response into typed weather data, including current conditions and a five-day forecast with temperature ranges and rain chances.

VIEW IMPLEMENTATION ＋ 
val url = URL(
  "https://api.weatherapi.com/v1/forecast.json" +
    "?key=\${BuildConfig.WEATHER_API_KEY}" +
    "&q=$encodedQuery&days=5&aqi=no&alerts=no"
)

The request runs on Dispatchers.IO, uses connection/read timeouts, and converts non-success HTTP responses into errors for the UI state to handle.

02 / AI BRIEFINGGROQ API

Weather data, explained.

After the forecast loads, a separate Groq request turns the supplied conditions into three concise points: how it feels outside, what to wear, and one useful thing to know. The prompt explicitly tells the model not to invent weather data.

VIEW IMPLEMENTATION ＋ 
append("Give 3 short bullet points: ")
append("what it feels like, what to wear, ")
append("and one useful thing to know. ")
append("Do not invent data.")

The briefing is optional UI data: current conditions and the forecast are placed in the success state first, then the state is updated when the briefing arrives.

03 / APP ARCHITECTURECOMPOSE + FLOW

State drives the screen.

A ViewModel exposes a StateFlow with explicit Idle, Loading, Success, and Error states. Jetpack Compose collects that state and renders the matching screen, keeping request logic out of the UI components.

VIEW IMPLEMENTATION ＋ 
sealed interface WeatherUiState {
  data object Idle : WeatherUiState
  data object Loading : WeatherUiState
  data class Success(
    val weather: WeatherData,
    val aiBriefing: String? = null
  ) : WeatherUiState
  data class Error(val message: String) : WeatherUiState
}

The search uses coroutines in viewModelScope; the network repositories switch to Dispatchers.IO for blocking HTTP work.
